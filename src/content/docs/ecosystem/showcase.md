## 🌐 浏览器自动化

### jkudish/jev-browser

**利用 Jev 进行无头浏览器操作与页面元素选择。**

传统做法是用通用 LLM 分析页面 DOM 并决定点击哪个元素——但一次调用动辄几秒，且输出需要复杂的解析与容错。用 Jev 的 `choice` 把"页面上可交互元素"作为候选集，可以做到：

- 页面元素选择变成一次 `choice` 调用（候选 = 页面上的元素列表，上限 255）
- 单步决策延迟压到百毫秒级
- 输出必定命中某个真实存在的元素，不会产生"幻觉选择器"

- 🔗 仓库：<https://github.com/jkudish/jev-browser>

## 💹 金融与交易

### jarrodwatts/jev-trader

**低延迟订单簿的毫秒级买卖决策。**

高频交易场景是延迟敏感度的极端案例——3 秒的 LLM 延迟在这里毫无意义。该项目利用 Jev 在 **300ms 量级**内完成对订单簿状态的买卖判断，把模型决策真正嵌入了交易主循环。

- 🔗 仓库：<https://github.com/jarrodwatts/jev-trader>
- ⚡ 关键词：低延迟、订单簿、300ms 级决策

## 🎮 游戏 AI

### typesafe-mario / Doom Bot

**10Hz 游戏高频动作决策状态机。**

这两个演示项目把 Jev 用在游戏 AI 上：以 **10Hz（每 100ms 一次）**的频率做动作决策，把游戏画面/状态作为 `state`，把"跳跃 / 前进 / 攻击 / 后退"等动作作为 `choice` 的候选标签。

值得一提的是它揭示的一种范式：**这里模型不是"聊天机器人"，而是嵌在游戏循环里的一个状态机转移函数**——这正是"软件原生"的含义。

- 📌 定位：技术演示 / 范式示范
- ⚡ 关键词：10Hz、实时状态机、游戏 loop

## 🛡️ Agent 安全

### jev-guard

**跨智能体工具调用的前置安全与风险拦截。**

在 Agent 架构中，最危险的时刻是"模型决定要调用一个工具"的瞬间。jev-guard 的思路是在工具调用真正执行之前，用 Jev 的 `noul` 做一次极低成本的`风险判断`：

```
Agent 决定调用工具
        │
        ▼
  【Jev】noul("这个动作有风险吗？")   ← 70ms，零输出成本
        │
   noul < 0.2 ──► 放行执行
   noul >= 0.2 ──► 拦截 / 升级人工确认
```

因为输出 Token 免费，这层守卫可以**无条件地加在每个工具调用前面**，而不需要担心成本。

- 📌 定位：Agent 安全 / Guardrail
- ⚡ 关键词：工具调用风控、多智能体
